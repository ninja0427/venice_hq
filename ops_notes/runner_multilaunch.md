# RUNNER の起動・多重起動・進捗判定

## 適用条件
runner を起動する・稼働状況やログを判定する時（主に人間オペレータ／検証時）。

## 手順
- 起動は常に `cd C:\Developer\Scripts\venice_cli` から始める。
  `C:\Windows\system32` のままだとログもモジュールも見つからない。
- 案件稼働は UI から起動する（分隊カード「この案件を1周」= `--once --project <案件名>`、
  CONTROL「ループを始める」= `--max-rounds N`）。`python runner.py` 直叩きは検証時のみ。
- `--project` は必須。省略起動は禁止（相対/絶対パス併存事故の再発防止）。
- 進捗の権威は `HQ\ledger.md` の `[cycle]` 行。runner.log と UI の稼働表示は当てにしない。

## 失敗と回避
- 同一案件を2つ同時に起動すると `[エラー] プロジェクト 'X' は既に起動中です` で
  スキップされ、**周回したように見えて何も進まない**。検証時は runner を1つだけ起動する。
- 「既に起動中です」は多重起動ロック（msvcrt.locking）。プロセス終了時に OS が解放するため
  残留しない。出たら実際に稼働中。`.locks\` のファイル削除は不要。
  `Get-CimInstance Win32_Process`（CommandLine）で実プロセスを確認する。
- runner を kill しても子プロセス（`main.py`）が残る。親子の両方を落とす。
- `runner.log` に出ていなくても周回は進んでいることがある。子プロセスの出力は
  リダイレクト先へ即時反映されない（`_alpha.log` が空でも周回中）。完走後に抽出すれば揃う。
- STOP ファイル（`HQ\STOP`）で全ループが次周回頭で停止する。ログは1周1回だけ出る。
