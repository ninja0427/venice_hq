# orders の読み方（LEAD）

## 適用条件
LEAD が周回頭で指示（orders）を受け取り実行に入る時。

## 手順
- orders の本文は起動プロンプトに**全文転記済み**。指示ファイル自体を探す必要はない。
- 実体パスは `Projects\HQ\orders\<案件>\NNN_<件名>.md`。**案件配下に orders ディレクトリは
  存在しない**。`Projects\<案件>\orders\` を探さない。
- 消費するのは `status.md` の `last_order` より大きい番号だけ。連番は単調増加・欠番許容・
  再利用なし。
- 指示文中に出てくるファイル名が実在しない時は `[LIST_DIR]` で1度だけ確認し、
  無ければ「未検出」と報告して次へ進む。

## 失敗と回避
- 実在しないファイル名を探して `Get-ChildItem -Recurse` の全文検索へ逃げない
  （Tier2）。上流（HQ）が誤ったファイル名を書いた場合、分隊側では解決できない。
  1度確認して無ければ未検出報告で打ち切る。
- 「bot_core.py が無い」のように指示のファイル名が旧設計の名残なことがある。実体は
  単一ファイル（例 vps_bot.py）。何周も同じ探索を繰り返さず、LIST_DIR 1回で確定して進む。
- 完了条件が READ_FILE / LIST_DIR / WRITE_FILE だけでは満たせない指示（例:
  実行手段の無い「削除」、到達不能な行番号報告）は構造的に完了不能。無理に迂回せず
  「到達不能」を報告する。人間が `_void\` へ退避し last_order を進めて解放する。
- 消費した order は必ず1アクション以上を実行してから締める。finish_reason=length で
  切れたまま終わると order だけ消えて作業ゼロになる（別スキル: 切断継続）。
